# ViPym Benchmark Evaluation Methodology

ViPym evaluates compressed language models against rigorous software engineering and code intelligence benchmarks to ensure that aggressive parameter reductions do not introduce regressions into real-world developer workflows.

---

## 1. Supported Evaluation Suites

| Suite Name | Focus Area | Task Format | Primary Metric | Sandboxing Requirement |
| :--- | :--- | :--- | :--- | :--- |
| **HumanEval / HumanEval+** | Python logic & algorithms | Function completion + 80x amplified tests | Pass@1 / Pass@k | Container / Subprocess |
| **MBPP / MBPP+** | Fundamental programming tasks | Function completion + unit tests | Pass@1 | Container / Subprocess |
| **BigCodeBench** | Diverse multi-library API usage (163 packages) | Script completion with realistic dependencies | Pass@1 / Compile Rate | Container |
| **Aider Multi-File Edit** | Repository refactoring & diff adherence | Multi-file unified diff application | Diff Syntax & Test Pass Rate | Subprocess |
| **SWE-bench Lite** | Real-world GitHub issue resolution | Git patch generation against real repositories | Resolved Issue % | Full Docker Sandbox |

---

## 2. Metrics & Observability

### 1. Quality & Accuracy Metrics
- **Pass@1 ($k=1$)**: Proportion of problems where the top generated candidate passes all automated unit tests.
- **Pass@k ($k \in [1, 5, 10]$)**: Unbiased estimator of passing probability with $k$ sampled completions:
  $$\text{Pass}@k = \mathbb{E}\left[ 1 - \frac{\binom{n - c}{k}}{\binom{n}{k}} \right]$$
- **Compile / Syntax Rate**: Fraction of generations that parse into a valid Abstract Syntax Tree (AST) without syntax or indentation errors.
- **Relative Quality Retention**: Percentage of baseline accuracy retained after compression ($\frac{\text{Pass@1}_{\text{compressed}}}{\text{Pass@1}_{\text{baseline}}} \times 100\%$).

### 2. Inference Telemetry & Resource Profiling
- **Time to First Token (TTFT, ms)**: Latency until the first completion token is emitted.
- **Inter-Token Latency (p50 / p95, ms)**: Per-token generation latency distribution under concurrency.
- **Effective Generation Throughput (tok/s)**: End-to-end token generation rate across concurrent streams.
- **Peak VRAM Footprint (GB)**: Maximum GPU memory consumed by weights, KV-cache, and activations during serving.
- **Cost per 1 Million Tokens ($/1M)**: Traceable operational cost modeled on AWS/GCP hourly GPU rates.

## 3. Sandboxing & Zero-Trust Execution

Evaluating code generated by compressed models introduces security risks (e.g. potential arbitrary command execution, infinite loops, resource exhaustion). ViPym enforces a multi-layered security architecture:

1. **AST Static Analysis**: Code is inspected before execution to catch syntax errors and flag forbidden system calls.
2. **gVisor / Docker Isolation**: Generated code executes inside disposable Linux containers with `runsc` virtualization, no network connectivity (`--network=none`), read-only root filesystems, and strict CPU/memory limits.
3. **Execution Timeouts**: Every test execution is bounded by an atomic process timeout (default: 15–30 seconds) to prevent infinite loops.
4. **Degraded Execution Double Opt-in**: Non-containerized local subprocess execution requires explicit opt-in via both configuration (`allow_unsafe_execution: true`) and environment variable (`VIPYM_ALLOW_UNSAFE=1`).

---

## 4. Statistical Significance

To ensure reproducibility and statistical validity:
- **Seed Control**: Fixed random seeds across calibration, generation, and sampling.
- **Measurement Repeats**: Multi-run evaluation repeats with mean and standard deviation reporting across benchmark passes.
